## 4. Claims that did not survive verification

### 4.1 `FAJRAK-MOBILE-2` is not fixed on build 74

`docs/sentry-investigation-2026-11-11.md` recorded the SIGSEGV as **"Confirmed Fixed"** — the
reasoning being that `sqlite3_flutter_libs` was removed in `3142ac4f`, eliminating the duplicate
native SQLite library. Sentry now shows a **fatal** SIGSEGV on **`3.47.8+74`**, dist 74, at
2026-11-11T08:01:06Z, with the issue back in `regressed`.

Removing the duplicate library was still the right change. It was not the whole cause, or not the
only cause. The doc keeps its original analysis and gained an append-only
`## Update — 2026-11-11T08:01Z (post-release monitoring result)` section that states the outcome
of its own monitoring recommendation; `PROJECT_CONTEXT.md` §4 now carries it as an **open P0**
rather than a resolved fix. `FAJRAK-MOBILE-S`, by contrast, held: no events after 2026-11-08.

`-W` (402 on alerts generation) and `-X` (PostgREST 504) are new signatures not covered by that
investigation. They are not the network-abort class the `notification_service.dart` fix addressed.

### 4.2 "Push to `main` deploys the web app" is false while paused

Several docs stated the Vercel auto-deploy as unconditional. With `live: false` it is not. The
pause is now attached to every deploy claim, and the incident runbook warns that a revert-push
will not move traffic until the project is unpaused.

### 4.3 The web suite is not "all passing"

`PROJECT_CONTEXT.md` §4 (and every doc that linked to it) said **832 web tests / 86 Jest
suites**, *all passing*. A fresh `npx jest --ci` measures **832 / 86** with **2 failures in
`__tests__/types/index.test.ts`**:

- `EXPENSE_CATEGORIES` is expected to contain **`صلة رحم`**; `types/index.ts` ships the typo
  **`صلاة رحم`**.
- The array is expected to have **10** entries; it has **11**.

Both landed in `08b3da52` (`fix(export): … rename 'دين' to 'تبرعات'`), which edited the Arabic
category list without updating the test. The counts are right; the green status is not. §4 now
says **830 pass / 2 fail**, and the failure is described there rather than hidden behind a
number.

### 4.4 CI is not green

`web (lint, typecheck, test, build)` fails on `ab17a74a` at the step **`Validate test counts
(web)`**, which runs *before* lint/typecheck/test. The validator exits non-zero on any failing
Jest test (by design — "fix the suite before validating counts"), so the red suite in §4.3 is
the whole cause. The job never reaches `npm run test`, which means the 2 failures are reported
in CI as a count-guard failure rather than a test failure, and the mobile job's
`Validate test counts (mobile)` passes.

Two other workflows fail for unrelated reasons:

| Workflow | Failure |
|---|---|
| `Migration structure guard` (`supabase-validate.yml`) | `supabase/migrations/20261107_rename_deen_to_tabarruat.sql` has an 8-digit date prefix; the guard accepts `<NNN>_` or `<YYYYMMDDHHMMSS>_` only |
| `Supabase Validate` | Fails alongside the guard on the same invalid filename |

The docs listed "daily backups to Cloudflare R2" as **resolved**. The `Supabase Daily Backup`
workflow has failed **every night since 2026-11-03** with:
